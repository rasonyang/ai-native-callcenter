# C33 闭合留证 — 2026-08-24

## 1. 修法(沿用 C29 在同一文件里立下的先例)

`queues` 三个非零默认列在 `NewQueue()` 里播种,而不是在 `validate()` 里兜底 ——
理由与 C29 的布尔一字不差:**不是零值的默认值也无法事后补** ,
因为 `validate` 分不清"操作员没写"和"操作员写了 0",两者都是 Go 的零值;
而 `CreateQueue` 的 INSERT 一一列出列名,列默认永远轮不到。

```go
func NewQueue() Queue {
    return Queue{
        IsEnabled:                true,
        IsRecordingEnabled:       true,
        DiscardAbandonedAfterSec: 60,
        RonaDelaySec:             10,
        SLAThresholdSec:          20,
    }
}
```

**没有第四个**:全库 catalog 三张表里,非零默认的整数列**只有这三个**;
`queues` 另外七个非零默认(strategy / moh_sound / tier_rules.waitSec / hours /
overflow / 两个布尔)此前已各有归属。

## 2. 现场

新建队列不带这三个字段:

```
POST /queues {"name":"c33probe","extNumber":"7098"}
→ discardAbandonedAfterSec: 60, ronaDelaySec: 10, slaThresholdSec: 20, isEnabled: true
```

(对照:2026-08-23 同一请求给的是 `0 / 0 / 0`。)

显式 0 仍然压过默认:

```
PUT …/queues/{id} {"name":"c33probe","extNumber":"7098","slaThresholdSec":0}
→ 60 / 10 / 0
```

探针队列已删除(`204`)。

## 3. 顺带修掉的一半:PUT 不再磨平这三个值

`NewQueue()` 同时供 create 与 update 使用,所以一个**没写这些字段的 PUT**
现在恢复默认,而不是写 0。这正是 support-zh 当初被怀疑的致零路径。

## 4. 关于"库里的受害者"

条目里"support-zh 现为 `0|0|0`"这一条**已于 2026-08-23 被 `f227bb1` 就地修复并声明作废**
(该 commit 自己写着"That edits C33's live evidence")。今日复查:

```
 support-en | 60 | 10 | 20
 support-zh | 60 | 10 | 20
```

`support-zh` 的 `updated_at` 仍是 08-13 的创建时刻 —— 修复走的是直接 UPDATE,不经 API。
**历史告诫不变**:在它读作 `0|0|0` 的那段时间里,凡在 support-zh 上量过的 SLA,
门限都是 0 秒而不是 20 秒。

## 5. 测试

`TestAnOmittedIntegerTakesTheDeclaredDefault` 三型:①不写 → 60/10/20;
②显式写 0 → 0 胜出;③PUT 不写 → 恢复默认而非归零。
已验证:去掉播种后 ①③ FAIL。与 C29 的 `TestAnOmittedBooleanTakesTheDeclaredDefault` 并排,
两半同源的缺陷从此有一对并列的守卫。
