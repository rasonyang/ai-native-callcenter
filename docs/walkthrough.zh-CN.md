# 功能走查（管理员 · 坐席 · 班长）

从一个空系统开始：管理员把平台搭起来，坐席接一通电话，班长在看板上确认它。

每一步都写清楚**在哪个页面做**、**做完应该看到什么**。看到的和写的不一样，就是一条缺陷 ——
在那一行下面加一行 `实际：…（时间）`，通话类问题往往要靠时间去日志里对回来。

| | |
|---|---|
| 入口 | `http://127.0.0.1:8080` |
| 登录口令 | `aicc@12345` |
| 话机 | web-sip-phone 浏览器扩展 |
| 话机口令 | 演示数据预置的分机是 `aicc@123`；自己新建的由系统生成，在分机页查看 |

---

## 前置：把系统跑起来

走查表从「用 admin 登录」开始，前提是下面这些都在跑。**每一项都给了自检命令**——
先把它们都跑通再往下走，否则后面失败的原因会分不清是系统没起还是功能有问题。

| # | 起什么 | 命令 | 自检 |
|---|---|---|---|
| 一 | PostgreSQL 与对象存储 | `docker compose -f deploy/dev/docker-compose.yml up -d` | `docker compose -f deploy/dev/docker-compose.yml ps` 两个服务都 healthy |
| 二 | FreeSWITCH | 本机原生安装，开机常驻 | `/usr/local/freeswitch/bin/fs_cli -x "status"` 输出 `ready` |
| 三 | 业务后端（bot 用） | `go run ./cmd/aicc-mockbackend -addr 127.0.0.1:8770` | `curl -s -X POST 127.0.0.1:8770/api/repair/status -d '{"rmaNo":"RMA1001"}'` 返回 `retCode 000000` |
| 四 | 应用 | `deploy/dev/restart.sh` | 打开 `http://127.0.0.1:8080` 出现登录页 |
| 五 | 话机 | web-sip-phone 浏览器扩展注册 | `/usr/local/freeswitch/bin/fs_cli -x "sofia status profile internal reg"` 里有你的分机 |

几件容易踩的：

- **第三项只有走第四节（Bot 能力）才需要**，第一到第三节不用它。但它必须在**应用启动之前**
  就位并写进 `.env`，因为地址是启动时读的：

  ```
  AICC_BOT_BACKEND_BASE=http://127.0.0.1:8770
  ```

  应用已经在跑才加这一行的话，得重启一次应用才生效。

- **`deploy/dev/restart.sh` 会顺带构建前端**。改过 `web/` 下的东西就必须用它，不能只
  `go build`——界面是编进二进制的（`go:embed web/dist`），只编 Go 会让浏览器继续拿到旧界面。

- **模型供应商**：本机 `.env` 用的是 `AICC_PROVIDER=qwen`，并且需要 `AICC_TRANSCRIBE_ENDPOINT`
  （工作区 id 在主机名里），缺了应用直接拒绝启动。openai 太贵，验证一律走 qwen。

- **每通 AI 电话都在花钱**。第四节的 bot 走查会真实调用模型，走之前想清楚要打几通。

> **先读这一条：中继不在这个界面里新增。**
>
> 中继（网关）定义在 FreeSWITCH 自己的配置文件里，平台只读它的状态，不写它。走查时能做的是
> **确认中继在位** —— 管理员的「概览 → 系统健康」会列出交换机报告的网关。如果那里写着
> 「无 —— 交换机没有报告任何网关」，说明交换机侧还没配好，后面所有对外的呼入呼出都走不通，
> 先停下来处理它。
>
> 你在界面里新增的是**号码**（DID），号码通过交换机已有的中继进出。

## 一 · 管理员：从零把平台搭起来

**这一段的顺序不能打乱。** 账号建好才有坐席身份，坐席配进队列队列才有人，流程发布了号码才有东西可绑。
每一步都依赖前一步的产物，所以这里编了号；后面两个角色是逐屏检查，不是流程，就没有编号。

### 账号与话机 · `/admin/users` · `/admin/extensions`

一个账号建出来的时候，话机就跟着来了 —— 不用单独去建分机。

- [ ] **1. 用 `admin` 登录**
      期望：进入「概览」。左侧菜单只有 *管理* 和 *系统* 两组，没有工作台和监控 —— 管理员不接电话。
- [ ] **2. 用户 → 新建账号，角色选「坐席」**
      期望：保存后列表里这一行的「分机」列**自动有了号码**。表单提示：坐席与主管会从号段里分到一部话机，管理员不接电话、不配话机。
- [ ] **3. 再建一个角色为「班长」的账号**
      期望：同样自动分到一部话机。班长既能看看板，也能自己接电话。
- [ ] **4. 再建一个角色为「管理员」的账号**
      期望：「分机」列显示 *无*。这是对的，不是漏了。
- [ ] **5. 分机 → 找到第 2 步那部话机 → 查看口令**
      期望：口令显示出来，并提示「这次查看会记入审计日志」。**记下它，装话机时要用。**
- [ ] **6. 尝试修改已建账号的登录名**
      期望：改不了。提示说明原因：坐席在交换机侧的名字由登录名派生。

### 坐席身份 · `/admin/extensions`（坐席与话机）

有账号还不等于是坐席。坐席身份把「账号 + 话机 + 交换机侧的名字」绑在一起。

- [ ] **7. 新增坐席，账号选第 2 步建的那个**
      期望：下拉里**只列出还没有坐席身份的账号**。已经是坐席的不会重复出现。
- [ ] **8. 填交换机名称，试着输入带空格的值**
      期望：被拒绝。提示：不能包含空格、@ 或引号。
- [ ] **9. 绑定话机，试着选一部已归别人的分机**
      期望：选不了或被拒。一个分机只能属于一个坐席。
- [ ] **10. 打开「自动应答」后保存**
      期望：保存成功。这决定队列来电是否无需点击就直接接通 —— 坐席那一段会验证它的实际效果。

### 队列与坐席配备 · `/admin/routing`

修改后立即下发到交换机 —— 不需要重启，也不需要另外点「应用」。

- [ ] **11. 新增队列，名称留空格试试**
      期望：被拒。提示：交换机使用，不能含空格、@ 或引号。
- [ ] **12. 正常建一个队列，不填队列分机**
      期望：系统**自动从号段分配**一个。建完后这个号**再也改不了** —— 提示明说：交换机和每一通被路由的电话都靠它认这个队列。
- [ ] **13. 设置最长等待为 `0`**
      期望：显示为 *不限*，不是 0 秒。
- [ ] **14. 把第 7 步的坐席配进这个队列**
      期望：保存后队列行显示已配备的坐席数。

### 机器人流程 · `/admin/bots`

草稿和线上是两回事。来电听到的永远是**已发布**的版本。

- [ ] **15. 新建流程，填标识和名称**
      期望：建完后**标识不可更改**（自动化靠它更新流程）。状态显示「从未发布 —— 还没有号码用这个流程接听」。
- [ ] **16. 在 JSON 编辑器里故意写坏一个字符 → 保存草稿**
      期望：当场提示「不是合法的 JSON」并指出问题；**没有把坏配置存进去**。
- [ ] **17. 写一个有孤立节点的流程（某阶段没有任何转移能到达）**
      期望：**能保存也能发布**，但编辑器上方出现橙色提醒并**点名是哪些节点**：「没有任何转移能到达：…。通话永远走不到那里。」
      这是有意的：孤立阶段运行时不坏任何东西，通话只是永远走不到那里，所以由编辑器提醒而不是服务端拒绝（`web/src/lib/flows.ts` 的 `unreachableNodes` 注释写明了理由）。
- [ ] **18. 改回正确的配置 → 保存草稿 → 发布**
      期望：发布提示说明影响面：此后接入的通话走新版本，**正在进行的通话仍用它开始时的版本**。版本列表里新版本标为「生效中」。

### 号码 · `/admin/numbers`

号码是外面的世界进入平台的门。每个号码都由机器人接听，队列只是机器人接不了时的兜底。

- [ ] **19. 新增号码，勾「可呼入」但不选机器人流程**
      期望：被拒或明确提示：能被打进来的号码，得有一个机器人流程来接。
- [ ] **20. 选上第 18 步发布的流程，兜底队列选第 12 步的队列，语言选中文**
      期望：保存成功。语言提示写明它决定**问候语、提示词语言与音色**三件事。
- [ ] **21. 再建一个号码，勾「可呼出」并设为「外呼未指定号码时用它」**
      期望：列表里这一行带「· 缺省」标记。这是坐席外呼时对方看到的主叫号。
- [ ] **22. 回到概览，看「系统健康」**
      期望：中继列出交换机报告的网关；队列、号码、坐席各自的数量与你刚建的一致；事件流显示在线控制台数。

### 对外集成与留痕 · `/admin/webhooks` · `/admin/audit`

- [ ] **23. 打开 Webhook 页**
      期望：能看，**不能建**。页面说明写着「订阅通过 API 创建，本页只做查看」。这是当前版本的设计，不是缺功能。
- [ ] **24. 用 API 建一个订阅后刷新此页**
      期望：列表出现该订阅。「令牌」列只显示 *已配置* 或 *无* —— 令牌本身在任何界面上都看不到。
- [ ] **25. 点一行订阅**
      期望：下方展开该订阅的近期投递：入队时间、通话、版本、投递状态、尝试次数、状态码、最后错误。
- [ ] **26. 打开审计日志，按 `/api/v1/queues` 过滤**
      期望：第 11–14 步的队列改动都在，带操作者、时间、来源 IP 和请求内容。第 5 步的口令查看也应该在这里。

## 二 · 坐席：签入、接一通、打一通

> **先装话机。** 用 web-sip-phone 浏览器扩展，以第 2 步分到的分机号注册，口令是第 5 步查到的那个。
> 注意**话机注册口令和登录口令不是同一个** —— 注册用的是分机口令，不是 `aicc@12345`。
> 话机没注册，后面所有接听都不会响。

### 工作台 · `/agent`

- [ ] **刚登录，还没签入**
      期望：提示「请签入话机后开始接听」。此时队列不会把电话给你。
- [ ] **点「签入」，再点「示闲」**
      期望：状态变为 *示闲*。班长的坐席页应当同步看到。
- [ ] **看「我的队列」**
      期望：列出你所属队列的等待人数；没人等待时显示「所属队列暂无人等待」。
- [ ] **从外面拨打第 20 步那个号码**
      期望：先听到**机器人**用你选的语言问候（不是直接转人工）。让机器人转人工，你的话机才响。
- [ ] **接听后看「当前通话」**
      期望：显示主叫号码与开始时间。若这个号码在客户库里，客户卡片一并显示；不在则显示「尚未识别来电客户」。
- [ ] **依次点保持 → 恢复 → 静音 → 取消静音**
      期望：每个动作都有反馈，状态与实际一致。会议按钮不可用，提示写明「平台没有可加入第三方的接口」—— 已知边界。
- [ ] **用拨号键盘按几个键**
      期望：提示「已发送 …」。每按一个键就立即发给对方，不是攒着一起发。
- [ ] **转接到另一个分机或队列分机**
      期望：通话转走，你的腿结束，状态进入话后处理。
- [ ] **挂断后填写「处理结果」和小结 → 完成**
      期望：状态从 *话后处理* 回到 *示闲*。今日统计里「接听通话」加一。
- [ ] **在「外呼」里输入一个外线号码 → 拨打**
      期望：提示「正在外呼 —— 将先接通您的话机」。**先响自己的话机**，接起后才拨对方。对方看到的主叫是第 21 步设的缺省外呼号码。

### 我的通话 · 客户 · 回访任务 · `/agent/calls` · `/agent/contacts` · `/agent/callbacks`

- [ ] **我的通话**
      期望：刚才那两通都在，最新在前，带客户、队列、处理结果、小结、通话时长。**只有自己的通话**，看不到同事的。
- [ ] **有录音的通话点「试听录音」**
      期望：播放器可播放/暂停、前后各跳 10 秒、可拖动定位。
- [ ] **客户 → 新增客户，号码填刚才来电的号码**
      期望：保存成功。**一个号码只对应一位客户** —— 再用同一号码新增应当被拒。
- [ ] **在备注里写一句，然后再从这个号码打进来**
      期望：通话中的客户卡片显示这条备注。这是备注存在的意义。
- [ ] **回访任务**
      期望：机器人在电话里承诺的回访汇集在这里。**先认领再回拨**；认领后该行标出「（我）」，回拨完点完成。

## 三 · 班长：看现场，也看昨天

> **最好和坐席同时开两个浏览器窗口走这一段。** 班长这些页面的价值全在「实时」二字上 ——
> 坐席那边点一下，这边应当几秒内跟着变。要验的不是数字对不对，是**它有没有跟着动**。

### 看板 · 坐席 · 队列 · `/supervisor` · `/supervisor/agents` · `/supervisor/queues`

- [ ] **登录后看菜单**
      期望：有 *监控* 和 *系统* 两组。菜单里看不到质检页 —— 当前版本已知未完成的功能。
- [ ] **让坐席在另一窗口签入 / 示闲 / 示忙**
      期望：坐席页的状态和「状态时长」**实时跟着变**，不用刷新。
- [ ] **让坐席关掉话机扩展**
      期望：话机列从 *正常* 变为 *无响应*；看板的「话机不可达」计数加一。这一项能提前发现「人在但接不到电话」。
- [ ] **对某个坐席点「强制签出」**
      期望：先弹确认，写明「其话机将立即停止接听来电」。确认后坐席那边状态立刻变为 *已签出*。
- [ ] **让一通电话进队列排队**
      期望：看板「队列内」计数上升；坐席工作台的「我的队列」同步显示等待人数。
- [ ] **看板整体**
      期望：可用坐席、通话中、今日通话/接听/放弃、**机器人闭环率**、平均排队等待都有数。闭环率是「机器人独立处理完、没转人工」的比例。
- [ ] **队列页**
      期望：每个队列的坐席配备、通话量、接听、放弃、平均等待、最长等待、服务水平。

### 通话记录与报表 · `/admin/cdr` · `/admin/reports`（班长与管理员共用）

这是三个角色里唯一两人共用的两个页面：班长看现场的一天，管理员看平台的账。

- [ ] **通话记录，找刚才那通呼入**
      期望：「通话轨迹」按实际经过展开，例如 *机器人 → 队列 → 坐席*。带机器人闭环、有录音等标记。
- [ ] **点进这一通的详情**
      期望：机器人时长、排队等待、通话时长、计费时长各自分开；挂断原因、业务数据、录音、转写都在同一页。
- [ ] **看这通电话的转写**
      期望：机器人说过的话有转写；**人工通话段目前没有**。纯人工通话（坐席点击外呼、内线）则完全没有转写。这是已记录在设计文档里的未完成项（`docs/design/08-transcription.md` D21），不是这次走查发现的缺陷。
- [ ] **找一通内线通话（坐席拨另一个分机）**
      期望：类型为 *内线*，**计费时长为 0** —— 两个分机之间通话不计费。
- [ ] **报表，切换今天 / 近 7 天 / 近 30 天**
      期望：通话量、接听、放弃、机器人闭环率、平均机器人时长按窗口重算；下方按队列和按日期分列。

## 四 · Bot 能力专项（管理员 · `/admin/bots`）

Bot 是这个产品的核心，所以单列一节。用五个从 java-bot 移植过来的经典用例走查
——它们覆盖了查询、多轮取值、身份校验、外呼回访、催收异议这几类真实业务：

| 流程 | 业务 | 阶段数 | 工具 | 特点 |
|---|---|---|---|---|
| `mobile_support` | 手机售后、查维修进度 | 5 | 1 | 最简单，适合先走这个 |
| `lead_qualification` | 新品回访、销售线索筛选 | 5 | 1 | 外呼场景，多轮取值 |
| `early_collections` | 账单提醒、记录付款安排或异议 | 8 | 3 | 分支最多 |
| `plan_change` | 宽带套餐变更 | 7 | 4 | 有身份校验环节 |
| `field_service_appointment` | 上门服务预约、改期、确认 | 9 | 5 | 阶段和工具最多 |

**怎么把它们放进来。** 文件在 `internal/seed/flows/` 下，打开复制整个 JSON，然后：

**机器人流程 → 新建流程** → 填标识（如 `mobile_support`）和名称 → 进 Designer →
把 JSON 粘进左侧编辑器 → 保存草稿 → 发布。

粘贴本身就是走查的一部分：粘进去就能看到右侧阶段图是否立刻画出来、Tools 和 Persona
两个标签页是否随之有内容。JSON 里的 `id` 和你填的标识是两个独立字段，不要求一致，粘过去不用改。

**HTTP 工具需要业务后端。** 这五个流程都要调接口取事实（查维修单、查账单、约上门），
后端不在时工具会失败——那是对的行为（bot 不该编造），但也就走不完流程。仓库自带一个：

```sh
go run ./cmd/aicc-mockbackend -addr 127.0.0.1:8770
# 然后在 .env 里：AICC_BOT_BACKEND_BASE=http://127.0.0.1:8770
```

它的数据是固定的，所以走查有确定的正确答案：`RMA1001` 在修、`RMA1002` 已寄出、
`92223333` 逾期 8 天共 45.60、`10086002` 在合约期内不能改套餐、`91234567` 已有一个预约。
机器人说的和这些对不上，就是它在编。

### 4.1 载入即校验

v2 是**加载期校验**——写错的东西在 `flowadd` 就被拒，不会等到通话中才发作。
每一条都改坏一处再 `flowadd`，看它拒不拒、错误说不说得清。

- [ ] **算子写错**（`"op": "SORTA_EQ"`）
      期望：拒绝，`phase welcome transition 0: unknown operator "SORTA_EQ"` —— 点名是哪个阶段的第几条转移。
- [ ] **转移指向不存在的阶段**
      期望：拒绝，`... targets "nowhere_at_all", which is not a phase in this flow`。
- [ ] **阶段允许了不存在的工具**
      期望：拒绝，`phase "welcome" allows unknown tool "no_such_tool"`。
- [ ] **`initialNode` 指向不存在的阶段**
      期望：拒绝，`initialNode "missing" is not a phase in this flow`。
- [ ] **删掉 `global.persona`**
      期望：拒绝，`global.persona is empty, so the model has no character to adopt`。
- [ ] **加一个孤立阶段（没有任何转移指向它）**
      期望：**不拒绝，能发布**。这是有意的，见上面第 17 步——由编辑器提醒，不由服务端拦。

### 4.6 v1 → v2 的能力差异（移植时记录）

这五个流程从 java-bot 的 v1 移植而来，差异如下。它们不是缺陷，是走查时会疑惑的点：

| | v1（java-bot） | v2（本项目） |
|---|---|---|
| 号码绑定 | 流程文件里写 `did: {zh: [...], en: [...]}` | 流程里**没有** did，号码在「号码」页绑定 —— 同一个流程可以被多个号码复用 |
| 挂断工具 | `hangup_call` | `hangup` |
| 留言工具 | 无 | **`take_message`**，且可以「拒绝」——队列关了就转成留言，拒绝是一次对话而不是一个错误 |
| 条件算子 | 只有 `eq` / `gte` | 14 个：`EQ NE GT LT GTE LTE IN NOT_IN CONTAINS NOT_CONTAINS IS_NULL IS_NOT_NULL IS_EMPTY IS_NOT_EMPTY`，且支持 `all` / `any` 嵌套 |
| 音色 | 无 | `global.voice`，随流程发布并版本化 |
| 转移事件 | `on_event: "tool:x"` | `on: "TOOL_RESULT"` + `tool: "x"`，另有 `NO_INPUT` |
| 成功标志 | 后端自定义 | 内置工具统一返回 `{"ok": "1"}` —— **是字符串不是布尔**，写条件时 `"value": "1"` |
| 后端地址 | 流程里 `api_base_env` 指定环境变量名 | **`apiBaseEnv` 字段不生效** —— 地址只来自部署配置 `AICC_BOT_BACKEND_BASE`。移植过来的流程里这个字段还在，是 v1 遗留，存了但没有任何东西读它 |

> **写条件时最容易错、错了还静默的一点**：`result.ok` 的值是字符串 `"1"` / `"0"`。
> 写成 `"value": true` 或 `"value": 1` 不会报错，只是条件永远不成立，转移永远不触发。
> 移植过来的五个流程可以直接当正确写法的样例。

## 已知的边界

下面这些走查时会碰到，**它们不是缺陷**，走查记录里不必重复登记。

- **中继在交换机侧配置**，界面只读它的状态。
- **质检页未开放**，班长菜单里看不到。
- **不支持会议**，通话控制里该按钮不可用并写明原因。
- **Webhook 只能看不能建**，订阅通过 API 创建。
- **人工通话没有转写**，只有机器人说过的话有（`docs/design/08-transcription.md` D21）。
- **只支持浏览器话机**，硬话机在路线图上。
- **孤立阶段不被服务端拒绝**，由编辑器提醒——运行时它不坏任何东西，通话只是走不到。
- **HTTP 工具需要后端在位**：移植来的五个流程都调业务接口（查维修单、查账单、约上门），
  `apiBaseEnv` 指向的后端不在时，工具会失败而不是编造答案——这是对的行为，但真机打电话
  验证 bot 全流程之前得先有那个后端。

## 怎么记结果

**通过就把 `[ ]` 改成 `[x]`**（VS Code 装 Markdown All in One、Typora、Obsidian 都能在预览里直接点）。

**不通过则保持 `[ ]` 不动**，在那一行下面加一行 `实际：`，写下真正看到的和当时的时间：

```markdown
- [ ] **17. 写一个有孤立节点的流程…**
      期望：服务端拒绝，并点名是哪些节点…
      实际：直接保存成功了，没有任何提示（2026-08-26 15:30）
```

三种状态因此一眼可分，不需要任何非标准语法：

| 样子 | 含义 |
|---|---|
| `[x]` | 通过 |
| `[ ]` + 有 `实际：` 行 | **不通过** |
| `[ ]` + 没有 `实际：` 行 | 还没走到 |

时间要记，通话类问题往往只能靠它去 `logs/aicc-*.log` 里对回来。

- 页面报错：记下错误原文，别只写「报错了」。
- 电话不通：先确认第 22 步的中继在位、话机已注册两件事，再往下判断。
- 数字对不上：记下你看的是哪个统计窗口（今天 / 近 7 天 / 近 30 天）。

统计进度：

```sh
grep -c '^- \[x\]' docs/walkthrough.zh-CN.md   # 已通过
grep -c '^- \[ \]' docs/walkthrough.zh-CN.md   # 未通过或未走到
grep -n '实际：'      docs/walkthrough.zh-CN.md   # 所有不通过项
```
