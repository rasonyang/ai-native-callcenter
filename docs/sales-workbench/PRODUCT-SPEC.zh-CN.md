# 销售 AI 外呼工作台改造说明

> 本文档描述本仓库面向 1–10 人销售团队的第一阶段改造范围。上游 AI Native Call Center 的电话引擎、AI 实时语音链路和既有外呼活动能力优先复用，不另起炉灶。

## 目标

在现有浏览器管理界面上，形成适合中文销售团队使用的轻量工作台：

1. 导入并维护客户名单。
2. 创建 AI 主动外呼活动，并能查看每位客户的拨打状态。
3. 配置销售身份、开场白、沟通目标、异议处理和结束条件。
4. 将通话记录整理为结构化客户分析。
5. 根据客户意向生成跟进任务和提醒。
6. 查看团队外呼数量、接通率、有效沟通率、意向分布和跟进完成率。

## 现有能力优先复用

- 外呼活动、联系人导入、去重、拨号调度和并发控制。
- FreeSWITCH 与现有语音供应商适配层。
- Flow/对话流程编辑与发布机制。
- 通话事件、CDR、录音和转写。
- 现有身份认证、角色权限、PostgreSQL 数据层、REST API 与 SSE 事件流。
- 现有报表和浏览器 UI 组件。

## 第一阶段改造范围

### A. 销售工作台入口
- 在现有管理导航中增加“销售工作台”入口。
- 汇总今日计划外呼、已拨打、已接通、待跟进、高意向客户。
- 所有指标必须来自真实 API 数据；没有后端数据时显示空态，不展示虚构数字。

### B. 销售话术模板
- 先用现有 Flow 系统承载话术，不平行开发第二套对话引擎。
- 提供可复制的中文销售流程模板：身份说明、来电目的、需求确认、价值说明、异议处理、下一步确认、礼貌结束。
- 支持变量占位符，如客户称呼、公司名称、活动名称和顾问身份。
- AI 必须尊重客户拒绝；明确要求停止联系时记录拒接状态并停止后续外呼。

### C. 通话后分析
每通电话结束后，目标结构化字段：
- 沟通结果：接通、未接、忙线、拒绝、无效号码、主动要求回访。
- 意向等级：高、中、低、无意向、待判断。
- 客户需求与当前管理痛点。
- 客户提出的异议及原话摘要。
- 客户承诺的下一步、建议跟进动作和建议时间。
- 摘要与分析依据应可回溯到通话转写；模型不确定时标记“待人工确认”。

### D. 跟进提醒
- 跟进任务关联客户、原始通话、负责人、计划时间和状态。
- 支持今日、逾期、未来七天筛选。
- 未经人工确认，不自动向客户再次拨号；自动外呼必须受活动时段、重试上限、拒接名单和频率限制约束。

### E. 销售统计
第一阶段统计：拨打总量、接通量、接通率、有效沟通量、高/中意向数、待跟进数、已完成跟进数。明确统计口径，避免把“接通”误算成“有效沟通”或“成交”。

## 安全与运营边界

- 初始开发和验收使用模拟线路或测试号码，不发起真实外呼。
- SIP 中继、语音模型和对象存储密钥仅通过环境变量或部署密钥注入，不提交到 Git。
- 上线前完成适用地区的营销外呼同意、AI 身份披露、录音告知、拒接/停止联系、数据保留与访问控制评估。
- 默认低并发；先单通电话端到端验收，再逐步提高并发。

## 开发顺序

1. 先完成现有代码与 API 契约审计，明确哪些字段/接口已存在。
2. 设计最小数据模型和 API 扩展；遵循项目契约先行原则，先改 OpenAPI，再生成 Go/TypeScript 代码。
3. 在现有管理界面增加销售工作台页面。
4. 复用 Flow 增加中文销售话术模板。
5. 增加通话后分析字段与人工复核状态。
6. 增加跟进任务和提醒。
7. 增加销售指标与测试；完成模拟线路端到端验收。

## 验收标准

- 可以导入一份客户 CSV，并看到每条记录的校验/导入结果。
- 可以创建销售外呼活动并用测试线路完成一通模拟外呼。
- 通话结束后有可查的记录、转写和结构化分析。
- 可将客户加入跟进队列并设置跟进时间。
- 工作台统计与后端数据一致。
- 拒接客户不会被后续活动再次拨打。
- 不将任何真实凭据或个人客户数据写入仓库。
